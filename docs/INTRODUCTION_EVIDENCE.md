## 项目解决什么问题

语言模型生成的数学证明可能缺少步骤或使用错误结论。Lean 是数学证明检查器；TRACER 组织候选生成、实际检查、错误反馈、可选例子检索、限次修复、独立复编译和证据保存。它目前不训练模型。

教学例子是：已知 x = y、y = z，目标 x = z。只用第一个条件不能完成目标；连接两个等式可通过 Lean。它仅解释工作流程，不计入效果统计。

## 当前能力与尚待检验的效果

| 已实现功能 | 具体作用 | 还不能据此声称什么 |
| --- | --- | --- |
| 目标项目中的真实 Lean 检查 | 判断候选是否通过，保留诊断 | 模型必然理解了数学 |
| 保留原文的错误整理 | 提供名称、类型、目标等信息及证据片段 | 摘要永远不丢信息 |
| 静态和随错误变化的检索原型 | 从本地材料补充相关例子 | 检索一定提高成功率 |
| 成功文件保存和独立复编译 | 使他人可重新检查形式有效性 | 自动排除所有题目或假设问题 |
| 失败包和浏览器演示 | 展示或重新复现预期错误 | 回放错误等于修复成功 |
| 执行前策略和 Linux 容器测试 | 提供已测控制项的有限证据 | 通用沙箱、未知攻击全面安全 |

三层报错以完整原文、统一格式和提取字段组织信息。提取字段对应原文片段是设计约束；总体忠实性和实际模型收益仍需专项分析。

## 当前研究与准备开展的工作

已经构建五项目 254 道历史修复测试题：Equational Theories 53、FLT 47、LeanAPAP 16、PFR 44、PhysLean 94。后者占 37.0%。原单项目占比 35% 门槛在模型调用前修订为 40%，完整披露见[基准说明](TRACER_REAL_V2.md)。项目级分开开发和测试，参考修复不进入模型生成流程。

当前受控比较以同一份首轮失败证明为起点，对比真实提示、普通重试、无关提示及改动内容的提示等信息。DeepSeek、GLM 开展更丰富的比较，MiniMax 检验三项共同核心条件。服务商覆盖是外部验证范围，不能替代算法和行为证据。完整审计后的最终新结果尚未公开，不能将部分运行或保存数量换算为最终效果。

后续先复用轨迹分析信息保留、编辑位置、错误转移和真实消耗，再单独预注册“一次改变一个诊断事实”的试验，之后用独立材料评估按错误选择提示。新的分析不回填成原先已注册内容，新规则不在已看过的最终测试集上调优后再声称独立收益。

## 用户能怎样体验

1. [网页演示](https://runqiwang777.github.io/TRACER/demo/)切换已保存的失败、诊断和修复，不调用模型或上传代码。
2. README 的本地命令使用固定候选，实际运行 Lean，体验验证与文件保存。它不衡量模型质量。
3. [API 指南](API_GUIDE.md)用于真实生成。付费请求会发送必要源码、提示及诊断，应使用自己确认可信的服务商。密钥不写进命令、提交或结果包。
