# TRACER v3 研究重点与贡献边界

更新日期：2026-11-02。本文整理当前研究定位和后续分析顺序，不修订运行中的 v3 预注册。

## 核心问题

在真实 Lean 项目的证明修复中，编译诊断何时能在相同生成机会下改善修复？效果是否随模型家族、项目、错误类别和诊断表示变化？

[Li 与 Li（2026）](https://arxiv.org/abs/2610.22698) 是反馈对照设计的重要参考。TRACER 以真实项目和多个一方模型 API 为研究对象，检验诊断表示与错误状态的条件效应。详细背景见[相关工作](RELATED_WORK.md)。

## 当前工作的独立价值

| 维度 | TRACER 已冻结或已实现的内容 | 完整实验后要回答的问题 |
| --- | --- | --- |
| 模型覆盖 | DeepSeek `deepseek-v4-pro`、智谱 `glm-4.5`、MiniMax `MiniMax-M3`；三家一方 API | 同样的反馈主对比能否在各模型中复现？哪些结论只适用于特定模型？ |
| 真实任务 | 五个独立 test 项目、254 道历史修复题、参考证明隔离 | 反馈效果能否跨项目成立？项目等权与题目等权的解释有何差异？ |
| 反馈表示 | raw、normalized、structured 及原始诊断证据片段 | 哪些错误类别需要结构化信息？压缩是否丢失有效信息？ |
| 检索与路由 | retrieval-only 和确定性 adaptive 原型 | 增加的上下文是否值得 token 与延迟成本？收益是否集中于某些错误？ |
| 证据交付 | 失败保留、逐次轨迹、独立复编译、AI 辅助复核、脱敏发布门禁 | 第三方能否追溯每个结论对应的请求、候选和 Lean 结果？ |

模型差异提供独立复现和外部有效性的研究价值。模型选择、真实任务和诊断表示的组合仍需由完整结果支持；不以“换了模型”单独宣称新方法或正面效果。不同论文的任务与推理服务不同，不能直接用总成功率排名。

## 保持当前实验可比

- 沿原输出目录和现有恢复机制完成当前批次；保留失败尝试，不因结论方向更换模型或重开。
- DeepSeek 与 GLM 保持八臂，MiniMax 保持三条确认臂，各三次重复。
- 主对比保持 `true_structured - content_free_retry`，同模型、同题、同重复、同首轮失败候选配对，按项目等权。
- 各模型首轮失败与合格种子可能不同。先报告各自纳入／排除与项目分布，再讨论模型间一致性，不将不同种子视为共享候选的配对。
- 冻结模型名是实验配置，不保证供应商永久固定服务端权重。发布时披露调用日期、实际返回的模型标识、thinking/reasoning 设置和可获得的版本信息。
- 相同调用次数、温度和最大输出上限不等于相同实际 token 消耗。token、延迟和可核实费用分别报告，未知价格不填 0。
- 既有主分析和停止门禁照原预注册执行。新提出的成本敏感性分析或分组分析，未预注册的部分标为探索性，不改写为先验假设。

## 完成当前批次后的执行顺序

| 顺序 | 工作 | 交付与解释边界 |
| --- | --- | --- |
| 1 | 完成性与资格审计 | 核对种子／分支计划、归档重试、缺失供体、策略拒绝、基础设施错误和未知结果预留；不把排除样本算作普通证明失败。 |
| 2 | 证明与发布审计 | 全部成功证明独立复编译，保存 AI 辅助复核及其方法；导出脱敏轨迹、配置、报告与可读清单。 |
| 3 | 冻结主分析 | 各模型分别给出项目等权主效应与预定区间，再进行预注册的跨模型方向一致性汇总。重复和实验臂不扩充独立题目数。 |
| 4 | 条件效应与机制分析 | 检查错误类别、项目、诊断表示、相关改动与错误转移；对未预注册分析保留探索性标签。 |
| 5 | 成本与实际使用价值 | 并列报告成功、生成次数、token、延迟及已知费用。成本匹配敏感性分析与冻结主结果分开呈现。 |
| 6 | 后续独立研究 | 依据结果决定是否开展学习式路由或新的安全隔离实验；另立协议与输出目录，不回写 v3。 |

当前仓库公开了题库与协议，但未包含全量审计后的 v3 provider 最终结果包。本文不根据公开文件缺失判断本机实验是否完成。

## 论文与首页的表述

首页突出真实项目、三供应商模型和证据可追溯的反馈表示；相关工作在正文中充分引用。最终贡献应依据结果描述“哪些条件下有效或无效”，保留零效应与负效应，不提前写成普遍提升。
